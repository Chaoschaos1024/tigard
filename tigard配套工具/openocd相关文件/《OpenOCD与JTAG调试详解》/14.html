OpenOCD与JTAG调试详解

第14讲：使用OpenOCD烧写Flash
flash命令集、编写与加载Flash算法、批量编程

引言

在嵌入式系统开发中，将固件程序烧写到目标设备的非易失性存储器（Flash）是至关重要的一步。OpenOCD不仅是一个强大的调试工具，也提供了完整的Flash编程能力。本讲将深入讲解如何使用OpenOCD的flash命令集、如何为特定Flash芯片编写和加载Flash算法，以及如何进行高效的批量编程。

1. OpenOCD Flash命令集详解

OpenOCD提供了一套完整的flash命令，用于检测、擦除、编程和验证Flash存储器。这些命令通常在OpenOCD的Telnet或GDB会话中执行。

1.1 基本Flash命令

命令 语法示例 功能描述
flash probe flash probe 0 探测并识别指定编号的Flash设备。
flash info flash info 0 显示Flash设备的详细信息（大小、扇区等）。
flash erase_sector flash erase_sector 0 0 10 擦除从第0扇区开始的连续11个扇区。
flash erase_address flash erase_address 0 0x08000000 0x1000 擦除从指定地址开始的一定长度区域。
flash write_bank flash write_bank 0 firmware.bin 0 将二进制文件写入Flash Bank的指定偏移地址。
flash write_image flash write_image erase firmware.elf 将镜像文件（ELF/HEX/BIN）写入Flash，可选擦除。
flash verify_image flash verify_image firmware.bin 0x08000000 验证Flash中的内容与镜像文件是否一致。
flash protect flash protect 0 0 3 on 启用或禁用指定扇区的写保护。

1.2 典型烧写流程示例

# 启动OpenOCD后，通过telnet连接（默认端口4444）
$ telnet localhost 4444

# 1. 探测Flash（假设是第一个Flash设备，编号0）
> flash probe 0
# 输出：Found Flash型号: STM32F4xx, base: 0x08000000, size: 0x00100000

# 2. 全片擦除（可选，write_image的erase参数也会擦除）
> flash erase_sector 0 0 last
# 或者擦除特定地址范围
> flash erase_address 0 0x08000000 0x10000

# 3. 编程ELF文件（包含地址信息）
> flash write_image erase firmware.elf
# 参数说明：erase 表示在写入前自动擦除所需扇区

# 4. 验证编程结果
> flash verify_image firmware.elf

# 5. 复位并运行程序
> reset run
提示： flash write_image 命令支持ELF、Intel HEX和原始BIN格式。对于BIN文件，必须指定加载地址，例如：flash write_image firmware.bin 0x08000000。

2. 编写与加载Flash算法

当OpenOCD不支持目标芯片的Flash时，或者需要优化烧写过程时，我们需要编写自定义的Flash算法（也称为Flash驱动）。Flash算法是一段运行在目标芯片RAM中的小程序，负责执行擦除、编程等底层操作。

2.1 Flash算法的关键组成部分

  • 初始化函数：配置Flash控制寄存器、时钟等。
  • 擦除函数：实现扇区擦除、整片擦除操作。
  • 编程函数：将数据写入Flash，通常需要处理字/半字编程。
  • 校验函数（可选）：验证写入的数据。
  • 信息结构体：描述Flash的几何结构（扇区大小、地址等）以及函数指针表。

2.2 编写一个简单的Flash算法（示例框架）

/* my_flash_algorithm.c - 适用于Cortex-M的简单Flash算法框架 */
#include <stdint.h>

/* Flash寄存器定义（示例，需根据具体芯片手册修改） */
#define FLASH_BASE       0x40023C00
#define FLASH_KEYR       (*(volatile uint32_t *)(FLASH_BASE + 0x04))
#define FLASH_SR         (*(volatile uint32_t *)(FLASH_BASE + 0x0C))
#define FLASH_CR         (*(volatile uint32_t *)(FLASH_BASE + 0x10))
#define FLASH_AR         (*(volatile uint32_t *)(FLASH_BASE + 0x14))

/* 算法函数 */
int flash_init(void) {
    /* 解锁Flash控制寄存器 */
    FLASH_KEYR = 0x45670123;
    FLASH_KEYR = 0xCDEF89AB;
    /* 等待Flash就绪 */
    while (FLASH_SR & 0x00000001);
    return 0; /* 0 = 成功 */
}

int flash_erase_sector(uint32_t sector_addr) {
    /* 设置擦除模式及扇区地址 */
    FLASH_CR |= 0x00000002; /* SER位 */
    FLASH_AR = sector_addr;
    FLASH_CR |= 0x00000040; /* START位 */
    /* 等待操作完成 */
    while (FLASH_SR & 0x00000001);
    /* 检查错误标志 */
    if (FLASH_SR & 0x0000001E) return -1;
    return 0;
}

int flash_program_word(uint32_t addr, uint32_t data) {
    /* 设置编程模式 */
    FLASH_CR |= 0x00000001; /* PG位 */
    /* 写入数据 */
    *(volatile uint32_t *)addr = data;
    /* 等待操作完成 */
    while (FLASH_SR & 0x00000001);
    /* 检查错误标志 */
    if (FLASH_SR & 0x0000001E) return -1;
    return 0;
}

/* Flash信息结构体 - OpenOCD通过此结构调用算法 */
struct flash_driver my_flash = {
    .name = "my_custom_flash",
    .flash_init = flash_init,
    .flash_erase = flash_erase_sector,
    .flash_write = flash_program_word,
    .sectors = {
        {0x08000000, 0x04000}, /* 扇区0: 16KB */
        {0x08004000, 0x04000}, /* 扇区1: 16KB */
        /* ... 更多扇区定义 */
        {0xFFFFFFFF, 0x00000}  /* 结束标记 */
    }
};

2.3 在OpenOCD中加载自定义算法

编写完算法代码后，需要将其编译为二进制文件，并在OpenOCD配置文件中加载。

# 在OpenOCD的配置文件（如 target.cfg）中添加
# 1. 声明Flash Bank，并指定算法文件
flash bank $_FLASHNAME cfi 0x08000000 0x00100000 2 2 $_TARGETNAME \
    my_flash_algorithm.bin 0x20000000

# 参数说明：
# $_FLASHNAME: Flash Bank的名称，通常为'flash'
# cfi: 使用通用Flash接口（此处仅为示例，实际可能是'stm32f1x'等）
# 0x08000000: Flash基地址
# 0x00100000: Flash大小（1MB）
# 2 2: 总线宽度等参数（具体含义依赖驱动）
# $_TARGETNAME: 关联的目标
# my_flash_algorithm.bin: 自定义算法二进制文件路径
# 0x20000000: 算法加载到目标RAM的地址
注意： 自定义Flash算法必须确保其代码和数据完全位于目标芯片的RAM中，并且不会与应用程序或OpenOCD自身使用的内存区域冲突。通常需要预留一块固定的RAM区域供算法使用。

3. 批量编程与生产脚本

在产品量产或需要频繁烧写多个设备的场景下，自动化批量编程至关重要。OpenOCD支持通过脚本和命令行参数实现无人值守的批量烧写。

3.1 编写批量烧写脚本

创建一个OpenOCD脚本文件（例如 batch_program.cfg），将整个烧写流程自动化。

# batch_program.cfg
# 批量烧写脚本示例

# 1. 接口与目标配置
source [find interface/jlink.cfg]
transport select swd
source [find target/stm32f4x.cfg]

# 2. 初始化
init
reset halt

# 3. 配置Flash（如果未在target.cfg中配置）
flash bank $_FLASHNAME stm32f2x 0x08000000 0x00100000 0 0 $_TARGETNAME

# 4. 擦除整个Flash
flash erase_sector 0 0 last
puts "Flash擦除完成。"

# 5. 编程固件文件
flash write_image erase /path/to/firmware.bin 0x08000000
puts "固件编程完成。"

# 6. 验证
flash verify_image /path/to/firmware.bin 0x08000000
if {[get_flash_status] == 0} {
    puts "验证成功！"
} else {
    puts "验证失败！"
    shutdown error
}

# 7. 复位并运行（可选）
reset run

# 8. 关闭OpenOCD
shutdown

3.2 使用命令行进行批量操作

通过命令行一次调用完成整个烧写过程，便于集成到CI/CD流水线或生产工具链中。

# 基本语法
openocd -f interface_config.cfg -f target_config.cfg -c "init; reset halt; flash write_image erase firmware.bin; reset run; shutdown"

# 实际示例（使用J-Link和STM32F4）
openocd \
    -f interface/jlink.cfg \
    -c "transport select swd" \
    -f target/stm32f4x.cfg \
    -c "init; reset halt; flash write_image erase firmware.elf; reset run; shutdown"

# 将命令写入脚本文件并执行
openocd -f batch_program.cfg

3.3 批量编程最佳实践

  1. 错误处理：在脚本中加入状态检查，确保每一步成功后再继续。
  2. 日志记录：使用log_output命令将输出重定向到文件，便于追溯生产问题。
  3. 速度优化：调整JTAG/SWD时钟频率至允许的最高值，并使用flash write_image的fast选项（如果算法支持）。
  4. 多设备流水线：通过脚本控制多路复用器或使用多个适配器，实现多设备并行烧写。
生产提示： 对于严格的量产环境，建议在烧写后读取Flash的校验和或CRC，并与原始文件对比，作为最终的质量检查步骤。OpenOCD的flash verify_image命令可以进行逐字节验证，但速度较慢。生产中可以只验证关键区域或使用硬件CRC单元加速。

总结

本讲详细介绍了使用OpenOCD进行Flash烧写的三大核心内容：丰富的flash命令集、自定义Flash算法的编写与加载方法，以及适用于量产的批量编程技术。掌握这些技能，将使你能够：

  • 灵活地对各种嵌入式Flash存储器进行编程、擦除和保护操作。
  • 为OpenOCD尚未官方支持的Flash芯片添加支持，或优化现有算法。
  • 构建自动化、高可靠性的生产烧写流程，提高开发和生产效率。

OpenOCD的Flash编程功能强大且可扩展，是嵌入式工程师工具箱中不可或缺的利器。结合JTAG/SWD调试功能，它实现了从代码烧写到调试的全流程覆盖。
