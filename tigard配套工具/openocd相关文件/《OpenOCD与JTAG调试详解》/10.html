1. 调试命令概述

OpenOCD 通过 Telnet 或 GDB 接口提供了一系列强大的调试命令，用于控制目标处理器的执行、访问内存和寄存器。这些命令是嵌入式调试工程师日常工作的核心工具。本讲将详细讲解最常用的一组基础命令。

OpenOCD 调试命令交互示意图

2. 核心调试命令详解

以下命令通常在 OpenOCD 的 Telnet 会话（默认端口 4444）或通过 GDB 的 monitor 命令执行。

halt

功能：暂停目标处理器的执行。

使用场景：中断正在运行的程序，以便检查寄存器、内存状态或设置断点。

# 暂停目标CPU
halt
# 输出示例：target halted due to debug-request, current mode: Thread

resume [address]

功能：恢复目标处理器的执行。可选参数指定恢复执行的地址。

使用场景：在暂停或单步执行后继续运行程序。

# 从当前地址继续执行
resume
# 从指定地址0x8000000继续执行
resume 0x8000000

step [address]

功能：单步执行一条指令。可选参数指定单步执行的地址。

使用场景：精细跟踪程序流程，逐条指令调试。

# 执行当前地址的一条指令
step
# 在地址0x8000100处单步执行
step 0x8000100

reset [run|halt|init]

功能：复位目标系统。可选参数控制复位后的行为。

参数：
run - 复位后自动运行
halt - 复位后保持暂停（默认）
init - 执行复位初始化但不启动

# 复位并保持暂停状态
reset
# 复位并立即运行
reset run
# 执行复位初始化
reset init

reg [name [value]]

功能：查看或修改CPU寄存器。

使用场景：检查寄存器值，修改PC、LR、SP等关键寄存器。

# 显示所有寄存器值
reg
# 显示特定寄存器r0的值
reg r0
# 将r1寄存器设置为0x20001000
reg r1 0x20001000

mww/mwh/mwb address value

功能：向指定内存地址写入数据。

区别：
mww - 写入字（32位）
mwh - 写入半字（16位）
mwb - 写入字节（8位）

# 向0x20000000写入32位值0xDEADBEEF
mww 0x20000000 0xDEADBEEF
# 向0x20000004写入16位值0xABCD
mwh 0x20000004 0xABCD
# 向0x20000006写入8位值0x12
mwb 0x20000006 0x12

3. 命令使用参考表

命令 语法 功能描述 常用示例
halt halt 暂停CPU执行 halt （暂停目标）
resume resume [address] 恢复CPU执行 resume 0x8000 （从指定地址恢复）
step step [address] 单步执行一条指令 step （单步执行）
reset reset [run|halt|init] 复位目标系统 reset run （复位并运行）
reg reg [name [value]] 读写CPU寄存器 reg pc 0x8000000 （设置PC寄存器）
mww mww address value 写入32位字到内存 mww 0x20000000 0x12345678
mwh mwh address value 写入16位半字到内存 mwh 0x20000000 0xABCD
mwb mwb address value 写入8位字节到内存 mwb 0x20000000 0x42

4. 典型调试流程示例

以下是一个完整的调试会话示例，展示了如何组合使用这些命令：

# 连接到OpenOCD的Telnet接口（默认端口4444）
# telnet localhost 4444

# 1. 暂停目标CPU
halt
# 输出：target halted due to debug-request, current mode: Thread

# 2. 查看当前寄存器状态
reg
# 输出：r0 = 0x00000000, r1 = 0x20001000, ..., pc = 0x08000124

# 3. 单步执行一条指令
step
# 输出：target halted due to single-step, current mode: Thread, pc = 0x08000128

# 4. 修改内存：向0x20000000写入测试数据
mww 0x20000000 0xDEADBEEF
mwh 0x20000004 0xABCD
mwb 0x20000006 0x12

# 5. 设置程序计数器，跳转到新地址
reg pc 0x08001000

# 6. 从新地址开始执行
resume
# 输出：resumed

# 7. 再次暂停目标
halt

# 8. 执行软复位，复位后保持暂停状态
reset halt
重要提示：在使用内存写入命令（mww/mwh/mwb）时，请确保目标地址是有效的、可写的内存区域。写入只读区域或非法地址可能导致错误或目标系统异常。

6. 最佳实践与注意事项

  • 执行顺序：通常先使用halt暂停目标，再进行寄存器或内存操作，最后使用resume恢复执行。
  • 内存对齐：使用mww、mwh时注意地址对齐要求（通常字访问需要4字节对齐，半字需要2字节对齐）。
  • 复位策略：根据调试需求选择合适的复位方式：
    • reset halt：复位后暂停，适合调试启动代码
    • reset run：复位后立即运行，适合快速重启测试
    • reset init：执行初始化但不启动，适合外设配置
  • 寄存器访问：不同架构的寄存器名称可能不同，ARM Cortex-M系列常用寄存器包括r0-r15, pc, lr, sp, psr等。
  • 错误处理：如果命令执行失败，检查目标是否已连接且处于暂停状态，以及地址是否有效。
