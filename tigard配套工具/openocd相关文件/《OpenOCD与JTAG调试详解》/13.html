第13讲：Flash编程基础

Flash存储器特性、擦除、编程、验证的基本流程

一、Flash存储器核心特性

Flash存储器是一种非易失性存储器，在嵌入式系统中用于存储固件、配置数据和用户信息。理解其特性是正确编程的前提。

1.1 主要类型与特点

类型 结构 擦除单位 编程单位 典型应用
NOR Flash 并行访问，地址数据线独立 扇区 (Sector, 4KB~128KB) 字/字节 (Word/Byte) 代码存储、XIP执行
NAND Flash 串行访问，类似块设备 块 (Block, 16KB~512KB) 页 (Page, 512B~4KB) 大容量数据存储
内部Flash (MCU) 集成在微控制器内部 页/扇区 (Page/Sector) 字/半字 (Word/Half-Word) 微控制器固件
关键特性总结：
  • 擦除前必须编程：Flash位只能从1变为0，擦除操作将整个区域恢复为1。
  • 有限的寿命：每个存储单元有擦写次数限制（通常1万~10万次）。
  • 读写不对称：擦除慢（毫秒级），编程较快（微秒级），读最快。
  • 需要特定命令序列：通过写入特定地址和命令字来控制内部状态机。

二、Flash编程基本流程

通过JTAG和OpenOCD对Flash进行编程，需遵循严格的四步流程，确保数据完整写入。

2.1 详细步骤说明

  1. 连接与初始化
    • 通过JTAG/SWD连接目标板。
    • OpenOCD识别Flash控制器或外部Flash芯片。
    • 配置时钟、电压等参数。
  2. 擦除目标区域
    • 整片擦除：擦除整个Flash芯片，时间较长。
    • 扇区擦除：仅擦除需要编程的扇区，效率高，常用。
    • 擦除后，目标区域所有位变为1 (0xFF)。
  3. 编程写入数据
    • 将二进制固件按编程单位（字/页）写入。
    • 通常需要轮询状态位或等待完成中断。
    • 编程过程中，1变为0，0保持为0。
  4. 验证与保护
    • 校验：读取已写入数据，与源文件比较，确保一致。
    • 写保护：可选，设置保护位防止误擦写。
    • 复位运行：复位CPU，从Flash启动新固件。

三、OpenOCD Flash编程实战

以下是通过OpenOCD命令行和TCL脚本进行Flash编程的典型操作。

3.1 常用OpenOCD Flash命令

# 1. 启动OpenOCD，加载配置文件
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg

# 2. 连接Telnet到OpenOCD (默认端口4444)
telnet localhost 4444

# 3. 在Telnet会话中执行Flash操作
# 探测Flash
flash probe 0

# 擦除整个Flash
flash erase_sector 0 0 0

# 或擦除特定扇区（例如从扇区5开始，共2个扇区）
flash erase_sector 0 5 2

# 编程bin文件到地址0x08000000
flash write_image erase firmware.bin 0x08000000
# 参数`erase`表示编程前自动擦除所需扇区

# 验证编程内容
flash verify_image firmware.bin 0x08000000

# 4. 复位并运行
reset run

3.2 TCL脚本示例

# flash_program.tcl
proc program_flash {firmware_file base_address} {
    # 初始化
    init
    reset halt

    # 访问Flash Bank 0
    flash probe 0

    # 擦除（整片）
    flash erase_sector 0 0 0
    puts "Flash erased."

    # 编程
    flash write_image $firmware_file $base_address
    puts "Firmware programmed."

    # 验证
    flash verify_image $firmware_file $base_address
    puts "Verification passed."

    # 复位运行
    reset run
    shutdown
}

# 调用函数，编程firmware.bin到STM32的Flash起始地址
program_flash "firmware.bin" 0x08000000
调试提示： 如果编程失败，请检查：1) 目标板供电是否稳定；2) JTAG/SWD连接是否可靠；3) Flash配置命令序列是否正确（参考芯片手册）；4) 时钟频率是否过高，尝试降低JTAG速度。

四、关键概念与故障排查

概念/问题 说明 解决方案
写保护 (Write Protection) Flash的某些区域被硬件或软件锁定，防止误写。 在擦除前，通过OpenOCD命令 flash protect 解除保护。
读保护 (Read Protection) 保护固件不被读取，提升安全性。 通过选项字节(Option Bytes)设置，一旦使能，整片擦除才能解除。
编程校验错误 验证时发现数据不一致。 检查电源稳定性；降低编程速度；确保擦除成功；检查Flash算法文件。
OpenOCD无法识别Flash flash probe 失败。 确认配置文件中的flash bank命令设置正确；检查目标芯片型号是否支持。
扇区边界对齐 编程数据未按扇区大小对齐可能导致错误。 确保编程起始地址是扇区起始地址；填充数据至扇区整数倍。
